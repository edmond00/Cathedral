This file is READ BY THE GAME, so keep the "llama.cpp build: bNNNN" format on the first line.
LlamaInstallCheck (src/LLM) asks llama-server for its real build at startup and warns, on the
loading screen and the main menu, when that build differs from LlamaInstallCheck.ExpectedBuild
or from the number written here. Each GPU backend pack carries its own BUILD.txt, checked the
same way. Upgrading: see the `models` skill.

Mixing backend DLLs across build numbers does not fail cleanly — ggml-base.dll and a backend
from different revisions share a C++ ABI that is not stable between them, so the symptom is a
crash inside the backend with no diagnostic. The backend's own BUILD.txt is what lets the game
turn that into a message, since the DLLs carry no version of their own.

── what was kept, and why ────────────────────────────────────────────────────────────────

This is a pruned copy of the upstream release. The full zip ships ~20 executables; a game
needs two, and every extra unsigned .exe is another SmartScreen/antivirus prompt for a player.

kept:
  llama-server.exe        the only thing the game actually runs
  llama-bench.exe         the first-run probe measures backends with this
  llama-server-impl.dll, llama-bench-impl.dll
                          since ~b11000 each .exe is a thin launcher over an -impl.dll that
                          holds the program itself; the .exe imports it, so it cannot go
  llama.dll, llama-common.dll, ggml.dll, ggml-base.dll, mtmd.dll
  ggml-cpu-*.dll          14 CPU backends, one per microarchitecture — see below
  libomp.dll              OpenMP runtime the CPU backends link against (was libomp140.x86_64.dll)
  LICENSE-LLVM-OpenMP     its license, since we redistribute it

The kept set is the PE import closure of llama-server.exe and llama-bench.exe, plus the CPU
backends (loaded by directory scan, so they appear in no import table). Recompute it on every
upgrade rather than copying this list: upstream's file layout changed between b8851 and b11515.

dropped:
  ggml-rpc.dll, ggml-rpc-server.exe    distributed inference across machines
  llama-cli/-tts/-imatrix/-quantize/-perplexity/-mtmd-*/-qwen2vl-* and the rest

── do not delete the ggml-cpu-* files ────────────────────────────────────────────────────

They look like duplicates and are not. ggml discovers backends by scanning THIS DIRECTORY at
startup and loading whichever initialise, then picks the best CPU variant for the host ISA.
Running llama-server.exe --version prints the choice it made, e.g.

    load_backend: loaded CPU backend from ...\ggml-cpu-skylakex.dll

Keeping only one of them means every player whose CPU does not match that one falls back to
a slower path, or finds no CPU backend at all. 18 MB is the price of running everywhere.

That same directory scan is how GPU support is added — see backends/README.md.
